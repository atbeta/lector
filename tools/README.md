# tools

验证工具。界面改动必须过这两道，缺一不可——它们量的是不同层面。

## `node tools/design-audit.mjs`

静态审计：只看 `tokens.css` / `app.css` 源码。

- 对比度（token 原始值，WCAG AA）
- 字阶档位、相邻档差、有没有小于 12px 的字号（CJK 底线）
- 阅读版心换算成「一行多少中文字」
- 悬空引用、硬编码颜色/时长绕过 token、彩色投影

算不出「上屏后到底可不可见」——半透明合成、层叠背景、真实字号它都看不到。

## `node tools/ui-verify.mjs`

渲染审计：用 Playwright 起真实 Chromium，量**页面实际画出来的东西**。

- 半透明合成后的真实对比度（`--border-strong` 叠 0.7 才是上屏的值）
- 表格是否真排成 N 列、单元格有没有塌陷
- 勾选/未勾选任务、引用条、复选框、分隔线是否真的可见
- 元素重叠、横向溢出、标题字阶是否单调递减
- 浅色/深色两套主题，以及 macOS 与 Windows 两种窗口版式（换 UA）

需要先起 dev server：`cd packages/editor && bun run dev`。
截图落在 `.shots/`（已 gitignore），失败会列出具体元素与实测数值。

## 为什么要有 ui-verify

第一轮设计只跑了静态审计，结论是「全面通过」；渲染审计一跑就发现
正文对比只有 4.63:1、已勾选任务被压暗到 3.27:1（读起来像禁用）、
表头下沿合成后只有 1.18:1。静态审计看不到这些，因为问题出在合成与命中,
不在 token 取值。
