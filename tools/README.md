# tools

验证工具。界面改动必须过这两道，缺一不可——它们量的是不同层面。

## `node tools/design-audit.mjs`

静态审计：只看 `tokens.css` / `app.css` / `reading-themes.css` 源码。

- 对比度（token 原始值，WCAG AA）
- 字阶档位、相邻档差、有没有小于 12px 的字号（CJK 底线）
- 阅读版心换算成「一行多少中文字」
- 悬空引用、硬编码颜色/时长绕过 token、彩色投影
- **阅读主题**：清单（`readingThemes.ts`）与样式（`reading-themes.css`）两侧不漏、
  `default` 主题块与 `tokens.css` 基线逐项一致、6 款主题 × 明暗的正文/次级/链接
  对纸面全部过 AA

后三条是手写色值的机器门：12 套纸墨是人工配的，改一处 `--muted` 就可能把某款主题
压到 3:1，而「主题读起来舒不舒服」这件事只有数字拦得住。

算不出「上屏后到底可不可见」——半透明合成、层叠背景、真实字号它都看不到。
CI 的 `check` job 会跑这一个（无需浏览器）。

## `node tools/ui-verify.mjs`

渲染审计：用 Playwright 起真实 Chromium，量**页面实际画出来的东西**。

- 半透明合成后的真实对比度（`--border-strong` 叠 0.7 才是上屏的值）
- 填充类表面有没有真的差出一档（1.03:1 等于「配了色但看不见」）
- 任务项的勾选框是否与正文同一行（这条曾整段坏掉而不自知）
- 表格是否真排成 N 列、单元格有没有塌陷
- 引用条 / 复选框边框 / 分隔线是否真的可见
- 块间距节奏、背景是否平铺、横向溢出、标题字阶是否单调递减
- 浅色/深色两套主题，以及 macOS 与 Windows 两种窗口版式（换 UA）
- 阅读版心与正文字号（这两个值由设置决定，不是 CSS 说了算）
- **视图模式**：分段控件三档、文字标签非空、唯一选中、`aria-checked` 与
  `html[data-mode]` 一致
- **阅读主题**：选了主题纸面真的变色、标定排版（字号/行距/栏宽）真的落到
  `--reading-*` 上、「书」的首行缩进与两端对齐真的生效
- 交互行为：插入段落的块级撤销、粘贴 HTML 转 Markdown（并进 CM 撤销链）、
  任务勾选撤销、代码块里粘贴不转 Markdown——这几件事只发生在「事件 → 状态」之间，
  只有真的按一次键、真的发一个 paste 事件才看得见

### 两个反复踩过的坑

- **修饰键要按平台走**：脚本里写死 `Meta+b`（⌘B）在 Linux/Windows 上什么都不做
  ——块内 CM 的 `Mod-` 绑定在那里是 Ctrl。断言会报「功能没生效」，而真因是脚本
  按错了键。脚本里统一用 `${MOD}`（见文件顶部）。
- **默认档是「阅读」**：点块不聚焦、不进编辑。任何要测编辑路径的段落，都要先切到
  「编辑」档，否则会在「等 `.cm-content`」上超时——超时信息完全指向不到真因。

跑法：

```bash
cd packages/editor && bun run dev &          # 先起 dev server
PLAYWRIGHT_BROWSERS_PATH=../../.tmp/pw-browsers \
  TMPDIR=../../.tmp node tools/ui-verify.mjs # 在 tools/ 下执行时
# 首次需装浏览器：bunx playwright install chromium
```

截图落在 `.shots/`（已 gitignore），失败会列出具体元素与实测数值。

## 为什么要有 ui-verify

第一轮设计只跑了静态审计，结论是「全面通过」；渲染审计一跑就发现
正文对比只有 4.63:1、已勾选任务被压暗到 3.27:1（读起来像禁用）、
表头下沿合成后只有 1.18:1。静态审计看不到这些，因为问题出在合成与命中，
不在 token 取值。

第二轮又暴露了同一类问题的另一面：**CSS 是对的、页面是错的**。
默认设置里的 `fontSize: 16 / readingWidth: 736` 覆盖了 CSS 标定，
任务项的包裹层结构让 `inline` 永远无法与 `<p>` 同行，
零高的空行缝建立 BFC 让相邻外边距时而相加、时而取最大。
这些都必须用渲染审计才看得见——所以新增的每一条断言，
都对应一个曾经真实发生过的 bug。
